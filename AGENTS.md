# Agents

Drive `contract-lint` from an LLM agent or non-interactive client. It lints a contract
for **internal-consistency defects** and gates on the result. Stable machine-readable
catalogs, data on stdout, humans on stderr, a small documented exit-code set, and a
byte-stable (timestamp-free) report.

`contract-lint` works standalone, and it also **composes with the contract-ops suite**:
it is the pre-signature quality gate (compare-cli gates *drift between versions*;
contract-lint gates *defects within one document*), shares the suite's agent conventions
(`--catalog json`, `--json`, exit codes), and can lint a draft or extract-cli's source
text. You don't need the rest of the suite to use it.

## Output contract

- **Default**: a human-readable table on **stdout**, plus a one-line summary.
- **Machine-readable**: pass **`--json`** for the locked report on stdout
  ([`docs/spec/lint-output.schema.json`](docs/spec/lint-output.schema.json)) or **`--sarif`** for
  SARIF 2.1.0 ([`docs/spec/lint-sarif.schema.json`](docs/spec/lint-sarif.schema.json); for
  code-scanning/CI annotations). `--json` and `--sarif` are mutually exclusive.
- The `--json` report is **deterministic and carries no timestamp** — the same input yields
  byte-identical output, so it diffs cleanly in CI and snapshot tests. It includes `ok`
  (boolean) and `exit_code`, a `summary` (`error`/`warning`/`total`/`by_rule`), and a
  `findings[]` array; each finding is `{ rule, severity, message, line, column?, excerpt }`.
- **`numbering_resolved`** (`true` / `false` / `null`) reports whether Word's automatic list
  numbering made it into the linted text. `true` means every numbered paragraph resolved (a
  document with none is also `true` — nothing to resolve is not a failure to resolve);
  `false` means it did not, and `broken-xref`/`numbering` findings are downgraded to warnings
  that say so; `null` means numbering isn't a concept for the input. See
  [docs/reference/docx-numbering.md](docs/reference/docx-numbering.md).
- **`--check`**: print nothing; communicate purely via the exit code (the leanest gate).
- **stderr** is for humans only: `--why` rationale (`[why] …`), warnings, the `demo` banner,
  and errors. stdout stays clean for piping (`| jq`, `> lint.sarif`).
- **Failure**: a one-line `error: <message>` on **stderr**, exit `2`. There is **no uniform
  JSON error envelope** — **branch on the exit code, not on the message.**

## Exit codes

| Code | Meaning |
|------|---------|
| `0` | Clean — no findings at or above `--fail-on`. |
| `1` | Gate tripped — one or more findings at or above `--fail-on` (default `error`). Designed for CI gating. |
| `2` | Bad usage / unreadable input — no such file, unknown flag/rule, `--json` together with `--sarif`, a `.pdf` without the `[pdf]` extra, or an invalid config. |

`--fail-on error` (default) trips only on errors; `--fail-on warning` trips on any finding;
`--fail-on none` never trips (report-only, always exit `0` unless usage/IO fails).

## Discovery

Never hardcode command, flag, or rule names — call the catalogs at startup:

```bash
contract-lint --catalog json    # {name, bin, version, description, commands[], exitCodes}
contract-lint rules --json      # {tool, version, rules:[{id, severity, default_enabled, description}]}
```

`--catalog json` is the suite-wide discovery contract (parallel to `extract --catalog json`,
`contract-vault --catalog json`). It is generated by walking the live argparse parser, so it
lists **every** command (`lint`, `rules`, `demo`, `completion`) and flag — complete and
accurate (`tests/test_catalog.py` asserts it never drifts). `rules --json` is the
tool-specific discovery extra (parallel to extract-cli's `fields`): the authoritative list of
rule ids and default severities, so you enable/disable/branch on real ids rather than guessing.

Shell completion: `contract-lint completion bash|zsh` emits a script; it calls a hidden
`contract-lint __complete …` helper.

## Failure → recovery

| Symptom | Diagnose | Recover |
|---|---|---|
| Exit `2`, "no such file" / "is a directory" | Bad path. | Pass a real file, or pipe text: `extract doc.pdf \| contract-lint - --format md`. |
| Exit `2`, "reading .pdf needs the optional extra" | `.pdf` reading needs a backend (`.docx` does not). | `pip install "contract-lint[pdf]"`, or convert first with `extract`. |
| `numbering_resolved: false` in the report | The document's automatic list numbering did not resolve; the numbers Word displays are **not** in the linted text. | `broken-xref`/`numbering` findings are already downgraded to warnings. Don't relay them as defects — check the document in Word, or run `--why` for the reason. |
| Exit `2`, "--json and --sarif are mutually exclusive" | Both machine formats requested. | Pick one. |
| Exit `2`, "unknown rule" / "invalid config" | A bad rule id in `--enable/--disable` or a malformed `.contract-lint.json`. | List valid ids with `contract-lint rules --json`; fix the config. |
| Exit `1` with `placeholder`/`broken-xref` errors | Real defects: unfilled blanks, dangling cross-refs. | Fix the document, then re-run. These block signing. |
| Too many `undefined-term` / `party-consistency` warnings | Heuristic noise on proper nouns / multiple legal entities. | `--disable undefined-term`, add `ignore` regexes in config, or inline `<!-- contract-lint: disable-line <rule> -->`. |
| Want warnings to gate too | Default `--fail-on error` ignores warnings. | Run with `--fail-on warning`. |

## Recommended usage

```bash
# Lean CI gate on a draft (no output, just the exit code):
contract-lint draft.md --check || echo "draft has blocking defects"

# Full machine-readable report for triage:
contract-lint draft.md --json | jq '{ok, summary, findings: [.findings[] | {rule, line, message}]}'

# Lint a freshly-filled draft straight from draft-cli, before sign-cli:
draft fill nda --vars vars.json | contract-lint - --format md --fail-on warning --check

# Emit SARIF for code-scanning:
contract-lint draft.md --sarif > contract-lint.sarif
```

The integration contract is the `--json`/SARIF/rules schemas under
[`docs/spec/`](docs/spec/). See [`docs/INTEROP.md`](docs/INTEROP.md).
